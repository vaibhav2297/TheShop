# Manual visual review

Visual acceptance belongs to the user across Plan, Resolve, Execute, E2E, Verify and Ship.

- Use supplied Figma URLs and MCP for design structure, measurements, variants, assets and component mappings.
- Preserve design references and responsive/state decisions in the plan. Do not maintain design JSON.
- Do not run automatic Figma screenshot comparisons, capture/correction loops or visual evidence gates.
- No visual scope, target table, reference exports, overlays, difference images, capture hashes or review files required.
- Existing plans' automated visual-proof tasks are superseded. Preserve their design intent; missing or stale captures do not block SDD stages.
- Report routes and known design deviations for manual review. Never claim visual acceptance without user confirmation.
- Explicit visual acceptance criteria use manual confirmation in Verify. Ordinary build, design-rule, behavioral and accessibility checks remain.

Legacy capture tools remain available only for an explicit request. Their evidence contract does not apply to normal SDD completion.
